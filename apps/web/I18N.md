# Internationalization (`apps/web`)

The site uses typed message catalogs under `src/core/i18n/`. Public URLs stay **without** a locale prefix (`/learn/`, not `/pt/learn/`).

## Supported locales

| Code | Language | BCP 47 (`<html lang>`) |
|------|----------|-------------------------|
| `en` | English (default) | `en` |
| `pt-BR` | Portuguese (Brazil) | `pt-BR` |
| `es` | Spanish | `es` |

Catalogs: `src/core/i18n/locales/en.ts`, `pt-BR.ts`, `es.ts`.

## Usage

```astro
---
import { t } from '@core/i18n';
const locale = Astro.locals.locale ?? 'en';
---
<p>{t('pages.learn.lead', undefined, locale)}</p>
```

Navigation labels: `mainNavItems(locale)`, `siteNavItems(locale)` from `@core/i18n`.

## How the locale is chosen

On each **server-rendered** request (see dev vs production below):

1. Cookie **`vs_locale`** (`en` | `pt-BR` | `es`) if present and valid  
2. Else **`Accept-Language`** (e.g. `pt` / `pt-BR` → `pt-BR`, `es-*` → `es`, `en-*` → `en`)  
3. Else **`en`**

Middleware sets `Astro.locals.locale` and `setRequestLocale()` so `t()` and `getMessages()` resolve strings during SSR/render.

The **language switcher** in the site header (EN / PT / ES) sets `vs_locale` (`Path=/`, `SameSite=Lax`, one-year `Max-Age`), mirrors to `localStorage`, and reloads the page so the next request picks up the cookie.

### Dev vs production

| Mode | Config | Locale in HTML |
|------|--------|----------------|
| **`pnpm dev`** | `astro.dev.config.mjs` merges `output: "server"` plus `@astrojs/vercel` (devDependency only) so middleware sees cookies; avoids the “no adapter” warning. Astro may log that `getStaticPaths()` is ignored on thin `src/pages/**/[slug].astro` wrappers — expected in server dev; `pnpm build` still uses static output and pre-renders those paths. | Cookie + middleware |
| **`pnpm build`** | `astro.config.mjs` only — default **static** output, **no adapter**; pre-renders **English** HTML into `dist/` for Vercel static hosting (`vercel.json` → `apps/web/dist`). | English only on static hosts |

To localize production HTML you need on-demand rendering (e.g. `export const prerender = false` on routes plus a deployment adapter, or a host that runs Astro middleware on every request). Client islands that call `getMessages()` after load also read `<html lang>` and the cookie.

## Adding or updating strings

1. Add keys to `locales/en.ts` (source of truth for `MessageKey` types).
2. Mirror values in `locale-flat/pt-BR.json` and `locale-flat/es.json` (or patch files under `locale-flat/`), then run:
   - `node src/core/i18n/build-locale-file.mjs pt-BR`
   - `node src/core/i18n/build-locale-file.mjs es`
3. Register new locale codes in `types.ts`, `catalogs.ts`, and `resolve.ts` if you add a fourth language.

## Out of scope (this pass)

Normative markdown, `content/*.json`, module guides, and spec chapters remain **English** in the repo until you add locale-specific content paths or a content routing strategy.
